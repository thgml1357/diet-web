# 다이어트 앱 — AI(Claude) 코치 가이드

> 이 문서는 **사용자 한 명의 다이어트 기록을 대신 입력·계획해 주는 AI(Claude)** 를 위한 설명서예요.
> 사용자가 채팅으로 "오늘 점심에 OOO 먹었어", "체중 67.8"처럼 말하면 → 이 문서대로 DB에 기록하고, 내일 계획을 짜 주세요.
> 이 문서만 읽어도 일할 수 있게 써 두었어요 (저장소를 못 열어도 됩니다).

## 0. 시작하기 — 처음 만난 사용자라면
1. 사용자가 **웹앱 링크**를 열어 이메일/비밀번호로 **회원가입**했는지 확인한다 (앱 로그인 화면의 '처음이에요').
2. 사용자에게 **이메일과 비밀번호**를 받아 이 세션에서만 쓴다 (파일·커밋·로그에 남기지 말 것). 아래 §2로 로그인한다.
3. 온보딩 질문을 한 번에 묻는다 (이미 앱 설정에 있으면 생략):
   - 키(cm) · 현재 체중 · 목표 체중 · 시작일(보통 오늘)
   - 아프거나 조심할 곳(허리·무릎·어깨 등), 복용 중인 약/질환 (있으면 운동·식단을 보수적으로)
   - 운동 장소: **집(맨몸)** / **헬스장(머신)** — 앱 설정 '운동 장소'와 맞출 것
   - 자주 먹는 음식, 못 먹는 음식(알러지·종교·비건 등), 식사 횟수
4. 답을 사용자 프로필로 기억한다 (Claude 메모리/노트가 있으면 거기에, 없으면 대화 맥락에). 이후 식단·운동은 이 프로필에 맞춘다.
5. 키는 앱 '설정 → 키'에서 사용자가 직접 넣거나, 아래 §3의 `users.height`(cm)에 PATCH로 넣는다.
6. 체중이 있으면 바로 **오늘~내일 계획**을 만든다 (§5, §6).

## 1. 앱 구조 (한눈에)
- **웹앱(PWA)**: 사용자가 폰에서 보는 화면. 탭: 오늘 / 할일 / 기록 / 통계 / 계획 / 설정. 아이폰은 Safari → 공유 → *홈 화면에 추가*.
- **Supabase(Postgres + Auth)**: 데이터 저장소. 모든 사용자가 같은 프로젝트를 쓰지만 **RLS 때문에 각자 자기 행만** 읽고 쓴다.
- **AI(당신)**: 사용자의 로그인 토큰으로 REST API를 호출해 기록/계획을 넣는다. 앱은 다음 새로고침 때 바로 반영된다.
- 앱의 '할일' 탭에서 사용자가 계획 항목을 체크(계획대로/다르게/안 함)하면 앱이 실제 기록(`daily_records`)으로 복사해 준다.

## 2. 접속·인증 (사용자 본인 계정으로)
Supabase URL/anon key는 공개값이다 (저장소 `web/config.js`에 있음). 사용자별 비밀번호만 비밀.
```bash
SUPABASE_URL=...      # web/config.js 의 SUPABASE_URL
ANON=...              # web/config.js 의 SUPABASE_ANON_KEY
TOKEN=$(curl -s "$SUPABASE_URL/auth/v1/token?grant_type=password" -H "apikey: $ANON" -H "Content-Type: application/json" \
  -d '{"email":"<사용자 이메일>","password":"<비밀번호>"}' | python3 -c "import sys,json;print(json.load(sys.stdin)['access_token'])")
USER_ID=$(curl -s "$SUPABASE_URL/auth/v1/user" -H "apikey: $ANON" -H "Authorization: Bearer $TOKEN" | python3 -c "import sys,json;print(json.load(sys.stdin)['id'])")
H=(-H "apikey: $ANON" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json")
```
- 토큰은 1시간짜리. 만료되면 다시 로그인.
- 읽기: `curl "$SUPABASE_URL/rest/v1/daily_records?select=*&order=date.desc&limit=14" "${H[@]}"`
- 쓰기(upsert): `POST /rest/v1/<table>?on_conflict=user_id,date` + 헤더 `Prefer: resolution=merge-duplicates,return=representation`, 본문 `[{"user_id":"$USER_ID","date":"2026-12-01",...}]`
- `service_role` 키는 **절대 요구하지도, 쓰지도 말 것** (모든 사용자 데이터를 열 수 있음). 이 가이드는 사용자 본인 로그인만 전제한다.
- 저장소가 있으면 `scripts/`의 도구를 쓰면 편하다: `.env`에 `DIET_USER_EMAIL`, `DIET_USER_PASSWORD`만 넣고
  `python3 scripts/log_entry.py ...`, `python3 scripts/write_plan.py ...` (옵션은 각 파일 상단 설명 참고, `--meals-json/--exercises-json` 지원).

## 3. 테이블과 JSON 형식
날짜는 `YYYY-MM-DD` (한국 사용자는 KST 기준 오늘). 한 사용자·한 날짜당 **1행** (`unique(user_id,date)`).

| 테이블 | 용도 | 주요 컬럼 |
|---|---|---|
| `daily_records` | **실제 기록** | `weight`(kg), `steps`, `calories_consumed`, `calories_burned`, `meals[]`, `exercises[]`, `note`, `inbody` |
| `meal_plans` | **식단 계획** (미래) | `meals[]` |
| `exercise_plans` | **운동 계획** (미래) | `exercises[]` |
| `users` | 프로필(본인 1행) | `height`(cm), `start_date`, `program_start`, `favorites[]` |

**meal 항목**: `{"type":"아침|점심|저녁|간식", "name":"현미밥", "grams":150, "kcal":230}`
**exercise 항목**: `{"category":"유산소|근력|스트레칭", "name":"맨몸 스쿼트", "duration":분, "sets":3, "reps":"10회", "kcal":30, "notes":"자세 팁"}`
**inbody** (측정한 날만): `{"weight":..,"fat_pct":..,"smm":..,"visceral":..,"whr":..}` — 체지방량·제지방량·BMR·BMI는 앱이 계산하니 저장하지 말 것.
**favorites 항목**: `{"name","grams","kcal","category"}`, category = 식사/간식/음료/디저트/기타.

### 계획 항목 상태 (앱 '할일' 탭에서 사용자가 체크)
- 계획 항목에 `st`가 붙는다: `done`(계획대로) / `swap`(다르게 — 실제 내용은 `actual`) / `skip`(안 함).
- **계획의 name/kcal 등 계획 필드는 절대 바꾸지 말 것.** 실제로 한 일은 `daily_records`에 `plan:true`(swap이면 `planned:<원래 이름>`)로 앱이 복사한다.
- 이미 체크된(`st`가 있는) 날의 계획을 다시 쓰면 체크가 사라지니, **오늘 이전/체크된 날은 덮어쓰지 말고** 미래 날짜만 교체한다.

### 기록(daily_records) 규칙
- **merge**: 먼저 그날 행을 읽고, 사용자가 말한 값만 바꾼다. 숫자는 말한 것만 덮어쓰고 `meals`/`exercises`는 **뒤에 append**.
- `calories_consumed`는 `meals[].kcal` 합계로 계산해서 같이 저장한다 (사용자가 따로 말하면 그 값).
- 칼로리를 모르는 음식은 일반적인 값으로 **추정하되 "추정"이라고 알려준다**. 모르면 사용자에게 양을 묻는다.
- 몸 상태·통증·특이사항은 `note`에 한 줄로.

## 4. 기록할 때마다 하는 일 (사용자가 "OO 먹었어/했어" 라고 하면)
1. 위 규칙대로 `daily_records`에 append/upsert.
2. 그날 `calories_consumed` 합계를 목표(§5)와 비교한다.
3. **다음 날(또는 가까운 미래) 식단 계획이 이미 있으면** 소폭 조정해서 다시 쓴다.
   오늘 많이 먹었으면 내일을 살짝 가볍게(예: −100~150kcal 정도), 적게 먹었으면 목표대로. 급격한 변동 금지, **주간 평균**이 목표에 맞게 완만하게. 하한(§5)은 절대 침범 금지.
4. 계획을 바꿨다면 사용자에게 **한 줄로** 알려준다. 기록 결과도 짧게 요약(오늘 섭취 / 목표 / 남은 kcal).

## 5. 칼로리 목표 · 식단 짜는 법
- **목표 kcal = 체중(kg) × 30 − 500**, 10 단위 반올림, **최소 1,300 · 최대 1,800**. (앱 `generatePlan`과 같은 공식. 체중은 가장 최근 기록값.)
  → 약 0.5kg/주 감량. **1,300kcal 아래 계획은 금지.** 사용자가 의사 지도 등으로 다른 값을 명시하면 그 값을 우선하되, 극단적이면(1,200 미만 등) 안전 안내.
- 하루 4끼 구성: **아침 · 점심 · 간식 · 저녁**. 각 항목은 `{type,name,grams,kcal}`이고 합계가 목표에 ±50 이내.
- 메뉴 원칙: 단백질(닭가슴살·계란·두부·생선·살코기·그릭요거트) + 통곡/현미/오트밀/고구마 + 채소·나물 중심. 한식 위주, 간단한 조리.
  패스트푸드·튀김·고칼로리 디저트·단 음료는 피한다. **최근 3일 먹은 메뉴와 겹치지 않게**, 사용자가 자주 먹는 음식(§0 프로필·`favorites`·최근 기록)을 우선.
- 앱 기본 추천 메뉴 4종 로테이션 예시 (kcal은 목표에 맞춰 비례 조정됨):
  - A: 오트밀·우유·바나나·삶은 계란 / 현미밥·닭가슴살 구이·나물·김치 / 그릭요거트·아몬드 / 연어구이·고구마·샐러드
  - B: 통밀빵·계란 스크램블·방울토마토·우유 / 현미밥·돼지 안심 볶음·쌈채소·된장국 / 사과·단백질 음료 / 두부스테이크·현미밥·브로콜리
  - C: 그릭요거트·그래놀라·블루베리·계란 / 나물 비빔밥 / 바나나·아몬드 / 닭가슴살 샐러드·고구마
  - D: 오트밀·두유·계란 2개 / 현미밥·고등어구이·나물·미역국 / 방울토마토·그릭요거트 / 소고기 우둔 구이·쌈채소·현미밥·계란찜
- 알러지·종교·채식 등은 프로필에 맞춰 대체. 당뇨·신장질환·임신·섭식장애 병력이 있으면 일반 계획을 쓰지 말고 전문가 상담을 권한다.

## 6. 운동 프로그램 (맨몸/헬스장)
**근거**: WHO 2020(주 150–300분 중강도 유산소 + 주 2일↑ 근력), ACSM(전신 근력 주 2–3일, 2–3세트×8–12회, 점진 과부하), 감량 시 총 활동 주 250분↑, 허리 보호에 맥길 빅3.
**임의로 새로 만들지 말고 이 구조를 지킨다** (주 2~3일 전신 근력 + 주 150~300분 유산소).

| 요일 | 내용 |
|---|---|
| 월·금 | 전신 근력 A (근력은 연속일 없음) |
| 수 | 전신 근력 B |
| 화·목·토 | 유산소 (화 40분 / 목 35분 인터벌 / 토 50분) |
| 일 | 회복: 가벼운 산책 30분 + 스트레칭 15분 |

**진행(점진적 과부하)**: `users.program_start`(= 프로그램 1주차의 월요일; 앱이 첫 로그인 때 자동 설정)부터 센다.
1~2주차 2세트×10회 → 3~4주차 3세트×10회 → 5주차~ 3세트×12회. (한쪽씩 하는 동작은 좌우 8회→10회.)

**근력일 구성**: 워밍업(빠르게 걷기 10분 / 헬스장은 사이클 10분) → 메인 4~5개 → **맥길 빅3** → 전신 스트레칭 5분.
- **집(맨몸) A**: 맨몸 스쿼트 · 글루트 브릿지 · 무릎 푸시업 · 엎드려 Y-T 레이즈
- **집(맨몸) B**: 리버스 런지(좌우) · 힙 힌지(맨몸) · 무릎 푸시업(천천히) · 옆으로 누워 다리 들기(좌우) · 엎드려 W 레이즈
- **헬스장 A**: 레그 프레스 · 힙 어브덕션 · 체스트 프레스 · 랫 풀다운 · 시티드 로우
- **헬스장 B**: 레그 프레스 · 시티드 레그 컬 · 숄더 프레스 · 랫 풀다운 · 체스트 프레스
- **맥길 빅3** (매 근력일): 맥길 컬업 · 사이드 플랭크(무릎 대고) · 버드독 — 각 3세트, 6-4-2회, 8초 버티기. **윗몸일으키기·부하 걸린 척추 굴곡 금지.**
- **유산소**: 집=빠르게 걷기/인터벌 걷기(빠르게 3분+보통 2분×7)/길게 걷기, 헬스장=트레드밀 경사 걷기/사이클 인터벌/트레드밀+사이클. 강도는 "말은 되지만 노래는 못 부를 정도".
- 집(맨몸)이면 **의자·생수병 등 집안 물건·덤벨은 쓰지 않는다.** 사용자가 헬스장에 등록하면 머신 루틴으로 바꾸고, 앱 설정 '운동 장소'를 헬스장으로 바꾸라고 안내한다.
- 항목마다 `kcal`(근력 세트 동작 15~35, 유산소는 분당 약 4~5)과 한 줄 `notes`(자세 팁)를 넣는다.
- 앱 '계획' 탭의 **추천 플랜** 버튼이 위 구조를 그대로 만들어 준다. AI가 직접 쓸 때도 같은 구성·같은 이름을 쓰면 일관된다.

**안전**: 사용자의 부상/통증 이력(§0)에 맞게 동작을 대체한다 (허리·무릎·어깨 부담 동작 제외). 통증이 심해지면 중단하고 병원 안내. 컨디션이 나쁘면 휴식으로 바꿔도 된다. 의료 조언은 하지 않는다.

## 7. 매일 밤 자동 계획 (선택 — 사용자가 원할 때만)
Claude Code 클라우드의 *예약 작업(Routine)* 이나 반복 작업을 쓸 수 있으면, 매일 밤 11:50(KST)에 다음 날 계획을 만들도록 설정한다:
1. 최근 7일 `daily_records`로 평균 섭취·자주 먹은 메뉴·운동 이행률을 본다.
2. §5 목표 kcal로 **내일** 식단을, §6 요일 구성(+진행 단계)으로 **내일** 운동을 만든다.
3. `meal_plans`/`exercise_plans`에 upsert(통째로 교체) → 사용자에게 3줄 이내 요약.
예약 작업이 없으면 사용자가 말을 걸 때(§4) 내일/이번 주 계획을 함께 점검한다.

## 8. 하지 말 것
- service_role 키 요청·사용, 다른 사용자 데이터 접근 시도.
- 1,300kcal 미만 계획, 극단적 절식·탈수 유도, 의료 진단.
- 계획 항목의 계획 필드(name/kcal) 수정, 체크된 날 계획 덮어쓰기.
- 인바디 파생값(체지방량·BMR·BMI) 저장.
- 사용자의 이메일/비밀번호/체중 등 개인 정보를 외부 서비스·커밋·로그에 남기기.

## 9. 문제 해결
- `401/JWT expired` → 다시 로그인. `42501`/빈 결과 → 토큰이 본인 것인지, `user_id`가 `$USER_ID`인지 확인.
- `column ... does not exist` (favorites/start_date/program_start/height/inbody/note) → 앱 주인이 `supabase/migrations/0003~0005`를 실행하지 않은 것. 주인에게 알린다.
